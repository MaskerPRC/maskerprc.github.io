    笔记

    PyTorch Mobile 已不再积极维护。请查看 ExecuTorch，PyTorch 全新的设备端推理库。您还可以查看 此页面 了解如何使用 ExecuTorch 构建 iOS 应用的相关信息。

    iOS

    要开始使用 iOS 上的 PyTorch，我们建议探索以下 HelloWorld。

    使用 Hello World 示例快速入门

    HelloWorld 是一个简单的图像分类应用程序，演示了如何在 iOS 上使用 PyTorch C++库。代码是用 Swift 编写的，并使用 Objective-C 作为桥梁。

    要求

    • XCode 11.0 或更高版本
    • iOS 12.0 或更高版本

    模型准备

    让我们从模型准备开始。如果您熟悉 PyTorch，您可能已经知道如何训练和保存模型。如果您不熟悉，我们将使用一个预训练的图像分类模型 - MobileNet v2，它已经包含在 TorchVision 中。要安装它，请运行以下命令。

    我们强烈建议您访问 Pytorch Github 页面以在您的本地机器上设置 Python 开发环境。


    pip install torchvision

    一旦成功安装了 TorchVision，请导航到 HelloWorld 文件夹并运行 trace_model.py 脚本。该脚本包含追踪和保存可以在移动设备上运行的 torchscript 模型的代码。


    python trace_model.py

    如果一切顺利，model.pt 应该生成并保存在 HelloWorld/HelloWorld/model 文件夹中。

    想了解更多关于 TorchScript 的详细信息，请访问 pytorch.org 上的教程

    通过 Cocoapods 安装 LibTorch-Lite

    PyTorch C++ 库在 Cocoapods 中可用，要将它集成到我们的项目中，只需运行

    pod install

    现在是时候在 XCode 中打开 HelloWorld.xcworkspace，选择一个 iOS 模拟器并启动它（cmd + R）。如果一切正常，我们应该在模拟器屏幕上看到一张狼的图片以及预测结果。

    代码讲解

    在这部分，我们将一步一步地讲解代码。

    图片加载

    让我们从图像加载开始。

    let image = UIImage(named: "image.jpg")!
imageView.image = image
let resizedImage = image.resized(to: CGSize(width: 224, height: 224))
guard var pixelBuffer = resizedImage.normalized() else {
    return
}

    我们首先从我们的包中加载图像并将其调整大小为 224x224。然后我们调用这个 normalized() 类别方法来归一化像素缓冲区。让我们更仔细地看看下面的代码。

    var normalizedBuffer: [Float32] = [Float32](repeating: 0, count: w * h * 3)
// normalize the pixel buffer
// see https://pytorch.org/hub/pytorch_vision_resnet/ for more detail
for i in 0 ..< w * h {
    normalizedBuffer[i]             = (Float32(rawBytes[i * 4 + 0]) / 255.0 - 0.485) / 0.229 // R
    normalizedBuffer[w * h + i]     = (Float32(rawBytes[i * 4 + 1]) / 255.0 - 0.456) / 0.224 // G
    normalizedBuffer[w * h * 2 + i] = (Float32(rawBytes[i * 4 + 2]) / 255.0 - 0.406) / 0.225 // B
}

    乍一看，代码可能看起来很奇怪，但一旦我们理解了我们的模型，它就会变得有意义。输入数据是一个形状为(3 x H x W)的 3 通道 RGB 图像，其中 H 和 W 至少为 224。图像必须加载到 [0, 1] 的范围内，然后使用 mean = [0.485, 0.456, 0.406] 和 std = [0.229, 0.224, 0.225] 进行归一化。

    TorchScript 模块

    现在我们已经预处理了输入数据，并且有了预训练的 TorchScript 模型，下一步就是使用它们来运行预测。为此，我们首先将模型加载到应用程序中。

    private lazy var module: TorchModule = {
    if let filePath = Bundle.main.path(forResource: "model", ofType: "pt"),
        let module = TorchModule(fileAtPath: filePath) {
        return module
    } else {
        fatalError("Can't find the model file!")
    }
}()

    注意，TorchModule 类是 torch::jit::mobile::Module 的 Objective-C 封装。

    torch::jit::mobile::Module module = torch::jit::_load_for_mobile(filePath.UTF8String);

    由于 Swift 不能直接与 C++通信，我们不得不使用 Objective-C 类作为桥梁，或者为 C++库创建 C 封装。为了演示目的，我们将所有内容都封装在这个 Objective-C 类中。

    运行推理

    现在是时候运行推理并获取结果了。

    guard let outputs = module.predict(image: UnsafeMutableRawPointer(&pixelBuffer)) else {
    return
}

    再次强调，predict 方法只是一个 Objective-C 包装器。在底层，它调用 C++ 的 forward 函数。让我们看看它是如何实现的。

    at::Tensor tensor = torch::from_blob(imageBuffer, {1, 3, 224, 224}, at::kFloat);
c10::InferenceMode guard;
auto outputTensor = _impl.forward({tensor}).toTensor();
float* floatBuffer = outputTensor.data_ptr<float>();

    C++ 函数 torch::from_blob 将从像素缓冲区创建一个输入张量。请注意，张量的形状是 {1,3,224,224}，它代表 {N, C, H, W}，正如我们在上一节中讨论的那样。

    c10::InferenceMode guard;

    上述行指示 PyTorch 仅进行推理。

    最后，我们可以调用这个 forward 函数来获取输出张量并将其转换为浮点缓冲区。

    auto outputTensor = _impl.forward({tensor}).toTensor();
float* floatBuffer = outputTensor.data_ptr<float>();

    收集结果

    输出张量是一个形状为 1x1000 的一维浮点数组，其中每个值代表从图像中预测出的标签的置信度。下面的代码对数组进行排序并检索前三个结果。

    let zippedResults = zip(labels.indices, outputs)
let sortedResults = zippedResults.sorted { $0.1.floatValue > $1.1.floatValue }.prefix(3)

    从源代码构建 PyTorch iOS 库

    跟踪 iOS 的最新更新，您可以从源代码构建 PyTorch iOS 库。

    git clone --recursive https://github.com/pytorch/pytorch
cd pytorch
# if you are updating an existing checkout
git submodule sync
git submodule update --init --recursive

    确保您已正确安装 cmake 和 Python。我们建议您参考 PyTorch 的 GitHub 页面来设置 Python 开发环境。

    构建适用于 iOS 模拟器的 LibTorch-Lite。

    打开终端并导航到 PyTorch 根目录。运行以下命令（如果您已经为 iOS 设备构建了 LibTorch-Lite（见下文），请先运行 rm -rf build_ios）：

    BUILD_PYTORCH_MOBILE=1 IOS_PLATFORM=SIMULATOR ./scripts/build_ios.sh

    构建成功后，所有静态库和头文件将生成在 build_ios/install 目录下

    为 arm64 设备构建 LibTorch-Lite

    打开终端并导航到 PyTorch 根目录。运行以下命令（如果您已经为 iOS 模拟器构建了 LibTorch-Lite，请先运行 rm -rf build_ios）

    BUILD_PYTORCH_MOBILE=1 IOS_ARCH=arm64 ./scripts/build_ios.sh

    构建成功后，所有静态库和头文件将生成在 build_ios/install 目录下

    XCode 设置

    在 XCode 中打开您的项目，转到项目目标的 构建阶段 - 链接库 ，点击加号并添加位于 build_ios/install/lib 中的所有库文件。导航到项目的 构建设置 ，将 头文件搜索路径 的值设置为 build_ios/install/include，并将 库搜索路径 设置为 build_ios/install/lib。

    在构建设置中搜索 其他链接器标志 。在下方添加自定义链接器标志

    -all_load

    要使用项目中的自定义构建库，请将以下代码替换 #import <LibTorch-Lite/LibTorch-Lite.h> （在 TorchModule.mm 中），这是使用通过 Cocoapods 的 LibTorch-Lite 时所需的代码：

    #include <torch/csrc/jit/mobile/import.h>
#include <torch/csrc/jit/mobile/module.h>
#include <torch/script.h>

    最后，通过选择构建设置，搜索 启用 Bitcode，并将值设置为 否 来禁用您的目标中的 Bitcode。

    在 CocoaPods 中使用 Nightly PyTorch iOS 库

    如果你想尝试添加到 PyTorch iOS 中的最新功能，你可以在你的 LibTorch-Lite-Nightly pod 中使用，它包含每晚构建的库：

    pod 'LibTorch-Lite-Nightly'

    然后运行 pod install 将其添加到你的项目中。如果你想将夜间 pod 更新到最新版本，你可以运行 pod update 来获取最新版本。但请注意，你可能需要使用最新的 PyTorch 在移动设备上构建模型 - 使用最新的 PyTorch 代码或通过命令如 pip install --pre torch torchvision -f https://download.pytorch.org/whl/nightly/cpu/torch_nightly.html 快速安装夜间版本，以避免在移动设备上运行模型时可能出现的模型版本不匹配错误。

    自定义构建

    从 1.4.0 版本开始，PyTorch 支持自定义构建。现在您可以构建只包含模型所需算子的 PyTorch 库。为此，请按照以下步骤操作

    1. 验证您的 PyTorch 版本为 1.4.0 或更高版本。您可以通过检查 torch.__version__ 的值来完成此操作。

    2. 要导出模型中的算子，例如 MobileNetV2，请运行以下 Python 代码行：

    import torch, yaml
model = torch.jit.load('MobileNetV2.pt')
ops = torch.jit.export_opnames(model)
with open('MobileNetV2.yaml', 'w') as output:
    yaml.dump(ops, output)

    在上述代码片段中，您首先需要加载 ScriptModule。然后，使用 export_opnames 返回 ScriptModule 及其子模块的算子名称列表。最后，将结果保存到 yaml 文件中。

    3. 要在本地使用上一步生成的算子 yaml 列表运行 iOS 构建脚本，请将 yaml 文件传递给环境变量 SELECTED_OP_LIST。同时，在参数中指定 BUILD_PYTORCH_MOBILE=1 以及平台/架构类型。以 arm64 构建为例，命令应该是：

    SELECTED_OP_LIST=MobileNetV2.yaml BUILD_PYTORCH_MOBILE=1 IOS_ARCH=arm64 ./scripts/build_ios.sh

    4. 构建成功后，您可以按照上面的 XCode 设置部分将结果库集成到您的项目中。

    5. 最后一步是在运行 forward 之前添加一行 C++代码。这是因为默认情况下 JIT 会对运算符（例如融合）进行一些优化，这可能会破坏与我们从模型中导出的运算符的一致性。

    torch::jit::GraphOptimizerEnabledGuard guard(false);

    使用 PyTorch JIT 解释器

    PyTorch JIT 解释器在 1.9 版本之前是默认解释器（我们 PyTorch 解释器的一种不是特别节省空间的版本）。它将在 1.9 版本中继续得到支持，并可以在 CocoaPods 中使用：


    pod 'LibTorch', '~>1.9.0'
