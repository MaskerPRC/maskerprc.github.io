2023年4月7日

与 AI 开发者一起庆祝 PyTorch 2.0 的新性能特性

由英特尔提供

向 PyTorch 基金会祝贺其发布 PyTorch 2.0！在这篇博客中，我讨论了英特尔为 PyTorch 2.0 做出的四个重大贡献的特性：

  1. TorchInductor
  2. GNN
  3. INT8 推理优化
  4. oneDNN 图形 API

我们在英特尔很高兴成为 PyTorch 社区的一员，并感谢与 Meta 同事的合作开发这些功能，并从他们那里获得反馈。

让我们开始吧。

1. 火炬 Inductor CPU FP32 推理优化

作为 PyTorch 2.0 编译堆栈的一部分，TorchInductor CPU 后端优化通过图编译在 PyTorch 惰性模式下实现了显著的性能提升。

通过利用来自 英特尔® PyTorch 扩展 的技术，TorchInductor CPU 后端在 Conv/GEMM 操作中实现了后操作融合和权重预打包，并通过 PyTorch ATen CPU 内核对内存绑定操作进行显式向量化，同时在基于 OpenMP* 的线程并行化之上，从而加速了 PyTorch 后端。

在 TorchInductor 代码生成中的强大循环融合之上，我们实现了对三个代表性深度学习基准（TorchBench、HuggingFace 和 timm1）的 1.7 倍 FP32 推理性能提升。训练和低精度支持正在开发中。

查看改进

在此触摸电感 CPU 性能仪表板上跟踪了各种后端上的性能提升。

提升 PyG 中图神经网络（GNN）在 CPU 上的推理和训练性能

GNN 是一种强大的分析图结构数据的工具。本功能旨在提升 GNN 在 Intel® CPU 上的推理和训练性能，包括新的第 4 代 Intel® Xeon®可扩展处理器。

PyTorch Geometric（PyG）是一个基于 PyTorch 构建的非常流行的库，用于执行 GNN 工作流程。目前，由于缺少 GNN 相关的稀疏矩阵乘法操作（即 SpMM_reduce）以及缺少针对 GNN 计算进行优化的几个关键内核级优化（scatter/gather 等），PyG 的 GNN 模型在 CPU 上运行缓慢。

为了解决这个问题，提供了相邻神经网络节点之间消息传递的优化：

  • scatter_reduce： 当边索引存储在坐标格式（COO）时，消息传递的性能热点。
  • gather：scatter_reduce 的反向计算，特别针对索引为展开张量的 GNN 计算进行优化。
  • torch.sparse.mm with reduce flag： 当边索引存储在压缩稀疏行（CSR）格式时，消息传递的性能热点。支持的 reduce 标志为：sum、mean、amax、amin。

在《加速 PyG 在 Intel CPU 上》中讨论了在 3 代 Intel® Xeon® 可扩展处理器 8380 平台和第 4 代 8480+平台上进行的推理和训练的端到端性能基准测试结果。

使用统一量化后端优化 x86 CPU 平台的 int8 推理。

新的 X86 量化后端是 Facebook 通用矩阵-矩阵乘法（FBGEMM）和 oneAPI 深度神经网络库（oneDNN）后端的组合，并取代 FBGEMM 成为 x86 平台的默认量化后端。结果：比 FBGEMM 更好的端到端 int8 推理性能。

用户默认使用 x86 量化后端访问 x86 平台，不同内核之间的选择在幕后自动完成。选择规则基于英特尔在功能开发期间进行的先前性能测试数据。因此，x86 后端取代 FBGEMM，可能提供更好的性能，具体取决于用例。

选择规则如下：

  • 在没有 VNNI（例如，Intel® Core™ i7 处理器）的平台，始终使用 FBGEMM。
  • 在具有 VNNI（例如，第 2-4 代 Intel® Xeon®可扩展处理器和未来平台）的平台：
    • 对于线性操作，始终使用 FBGEMM。
    • 对于卷积层，当层数大于 100 时使用 FBGEMM 进行深度卷积，否则使用 oneDNN。

注意，随着内核的不断发展。

上述选择规则将根据性能优化进行调整。在 [RFC] Unified quantization backend for x86 CPU platforms #83888 中讨论了统一 x86 后端与纯 FBGEMM 的吞吐量加速比性能指标。

利用 oneDNN Graph API 加速 CPU 上的推理

oneDNN 图形 API 扩展了 oneDNN，提供了一个灵活的图形 API，以最大化在 Intel® AI 硬件上生成高效代码的优化机会。它自动识别要加速融合的图形分区。融合模式专注于融合计算密集型操作，如卷积、矩阵乘法及其相邻操作，适用于推理和训练用例。

目前支持 BFloat16 和 Float32 数据类型，并且只能优化推理工作负载。BF16 仅在具有 Intel®高级向量扩展 512 (Intel® AVX-512) BF16 支持的机器上优化。

在 PyTorch 中支持新的 oneDNN 图形融合/优化内核时，通常不需要或只需要少量修改。要使用 oneDNN 图形，用户可以：

  • 在 JIT 跟踪模型之前使用 APItorch.jit.enable_onednn_fusion(True)，或者……
  • 使用其上下文管理器，即 with torch.jit.fuser(“fuser3”)。
  • 为了加速 BFloat16 推理 ，我们依赖 PyTorch 的 eager-mode AMP（自动混合精度）支持并禁用 JIT 模式的 AMP。

请参阅 PyTorch 性能调优指南 。
