2018年1月19日

PyTorch，一年回顾...

由 PyTorch 团队编写

今天是 PyTorch 公开发布一周年纪念日。这一年过得非常精彩——我们致力于构建一个灵活的深度学习研究平台。在过去的一年里，我们看到了一个令人惊叹的社区，人们在使用、贡献和推广 PyTorch——感谢大家的支持。

回顾过去一年，我们想要总结 PyTorch 的发展：进步、新闻和社区亮点。

社区

我们有幸拥有一个强大的有机社区，其中研究人员和工程师都爱上了 PyTorch。核心团队由来自多个国家、公司和大学的工程师和研究人员组成，没有每个人的贡献，我们无法将 PyTorch 打造成现在的样子。

研究论文、软件包和 GitHub

发布后不久，社区用户就开始将他们最喜欢的论文实现为 PyTorch，并在 GitHub 上发布代码。开源代码是研究人员今天的主要和基本工具。

人们聚集在一起创建了 torchtext、torchvision 和 torchaudio 包，以帮助促进和民主化不同领域的科研。

基于 PyTorch 的第一个社区包由 Brandon Amos 创建，名为 Block，有助于更轻松地操作块矩阵。随后，卡内基梅隆大学的 Locus Lab 发布了 PyTorch 包和大部分研究实现。第一篇研究论文代码由 Sergey Zagoruyko 撰写，题为更加关注注意力 。

来自加州大学伯克利分校的 Jun-Yan Zhu、Taesung Park、Phillip Isola、Alyosha Efros 及其团队发布了广受欢迎的 Cycle-GAN 和 pix2pix，该技术可以进行图像到图像的转换。

哈佛 NLP 和 Systran 的研究人员开始开发和改进基于 PyTorch 的 OpenNMT，这一项目最初由 Facebook 的 Adam Lerer 对 LuaTorch 代码的初始重实现所启发。

魔法独角兽团队在 Twitter 上早期贡献了他们的 超分辨率工作 到 PyTorch 的示例中。

Salesforce Research 发布了多个包，包括他们重点推出的 PyTorch-QRNN，这是一种比经过 CuDNN 优化的标准 LSTM 快 2 倍到 17 倍的 RNN。James Bradbury 和团队是 PyTorch 社区中最活跃和最具吸引力的力量之一。

我们发布了 @PyTorch-QRNN，比 NVIDIA 的 cuDNN LSTM 快 2-17 倍。

速度得益于 50 行 CUDA 通过 CuPy 实现。https://t.co/KaWhN4yDZdpic.twitter.com/yoLYj3pMI0


— Smerity (@Smerity) 2017 年 10 月 9 日

来自 Uber、 东北大学 和 斯坦福大学 的研究人员共同组建了一个围绕他们的包 Pyro 和 ProbTorch 的活跃概率编程社区。他们正在积极开发 torch.distributions 核心包。这个社区非常活跃且发展迅速，我们在 NIPS 2017 上举办了第一次 pytorch-probabilistic-programming 研讨会，Fritz Obermeyer、Noah Goodman、Jan-Willem van de Meent、Brooks Paige、Dustin Tran 和 22 名其他与会者讨论了如何让世界变得更加贝叶斯化。

NVIDIA 研究人员发布了三个高质量的仓库，实现了 pix2pix-HD、Sentiment Neuron 和 FlowNet2 论文。他们对 PyTorch 中不同 数据并行模型的可扩展性 的分析对社区很有帮助。

Allen Institute for AI 发布了 AllenNLP，其中包含 NLP 领域的几个最先进模型——标准 NLP 任务的参考实现和易于使用的 网络演示 。

我们也在 7 月份迎来了我们的第一个 Kaggle 获奖团队 grt123。他们在 2017 年数据科学 Bowl 比赛中赢得了肺癌检测，随后发布了他们的 PyTorch 实现 。

在可视化方面，Tzu-Wei Huang 实现了 TensorBoard-PyTorch 插件 ，Facebook AI Research 发布了 PyTorch 兼容的 visdom 可视化包。

最后，Facebook AI Research 发布了多个项目，如 ParlAI、fairseq-py、VoiceLoop 和 FaderNetworks，这些项目实现了多个领域的尖端模型并界定了数据集。

由于篇幅限制，我们未能突出展示无数优秀的项目，您可以在这里找到精选列表。

我们也要向在论坛上积极帮助他人的朋友们表示衷心的感谢，特别是 ptrblck、jpeg729、QuantScientist、albanD、Thomas Viehmann 和 chenyuntc。你们提供了宝贵的帮助，非常感谢！

指标

仅从数量上来说，

  • 在 github 上有 87,769 行 Python 代码，其中 import torch
  • GitHub 上有 3,983 个仓库在名称或描述中提及 PyTorch
  • PyTorch 的二进制文件下载量超过五十万次，确切数字为 651,916 次。
  • 5,400 名用户发表了 21,500 篇帖子，讨论了 5,200 个主题，在我们的论坛 discuss.pytorch.org（http://discuss.pytorch.org/）上。
  • 自发布以来，Reddit 的/r/machinelearning 板块有 131 次提及 PyTorch。在同一时期，TensorFlow 被提及 255 次。

研究指标

PyTorch 是一个以研究为导向的框架。因此，一个感兴趣的指标是查看 PyTorch 在机器学习研究论文中的使用情况。

  • 在最近的 ICLR2018 会议投稿中，PyTorch 被提及于 <强 id=0>87 篇论文 ，与 TensorFlow 的 228 篇论文、Keras 的 42 篇论文、Theano 和 Matlab 的 32 篇论文相比。

  • 框架每月 arxiv.org 提及次数中，PyTorch 有 72 次提及，TensorFlow 有 273 次提及，Keras 有 100 次提及，Caffe 有 94 次提及，Theano 有 53 次提及。

课程、教程和书籍

当我们发布 PyTorch 时，我们拥有良好的 API 文档，但我们的教程仅限于几个 ipython 笔记本——有帮助，但还不够好。

萨桑克·奇拉穆库尔蒂 自告奋勇，将教程改版成今天这个美丽的网站 。

肖恩·罗伯逊 和 贾斯汀·约翰逊 编写了出色的新教程——涉及 NLP，并通过实例学习。 尹哲·崔 编写了一篇美丽的教程，其中大多数模型都在 30 行或更少的代码中实现。每个新的教程都帮助用户更快地找到自己的学习路径，提供了不同的学习方法。

郭克文和戴利普·劳将他们正在编写的书籍代码内容切换到了使用 PyTorch。

我们已经看到很多大学将 PyTorch 作为主要工具教授机器学习课程，例如哈佛大学的 CS287。更进一步，为了普及学习，出现了三个使用 PyTorch 的在线课程。

  • Fast.ai 的 “编码者的深度学习”是一个受欢迎的在线课程。在九月，杰里米和雷切尔宣布 ，下一阶段的 fast.ai 课程将几乎全部基于 PyTorch。
  • 与新加坡国立大学和清华大学有联系的学者 Ritchie Ng 发布了一门 Udemy 课程 ，名为《使用 PyTorch 的实用深度学习》。
  • 香港科技大学（HKUST）的 Sung Kim 发布了一门面向大众的在线课程 ，名为“PyTorch 从零到精通”。

工程学

过去一年中，我们实现了多个功能，全面提升了性能，并修复了大量 bug。我们完成的工作的完整列表可以在我们的发布说明中找到。以下是过去一年我们工作的亮点：

高阶梯度

随着多篇实现梯度惩罚的论文的发布以及二阶梯度方法的持续研究，这成为了一个必要且备受期待的功能。在八月，我们实现了一个通用接口，可以接受 n 阶导数，并随着时间的推移增加了支持高阶梯度的函数覆盖率，以至于在撰写本文时，几乎所有操作都支持这一功能。

分布式 PyTorch

在八月，我们发布了一个遵循高度流行的 MPI-collective 方法的轻量级分布式包。该包具有 TCP、MPI、Gloo 和 NCCL2 等多个后端，以支持各种类型的 CPU/GPU 集体操作和用例，并集成了 Infiniband 和 RoCE 等分布式技术。分布式技术难度较大，我们在初始迭代中遇到了一些 bug。在随后的版本中，我们使该包更加稳定并提高了性能。

更接近 NumPy

用户最大的需求之一就是希望拥有他们熟悉的 NumPy 功能。例如广播和高级索引等功能既方便又节省用户大量冗余。我们实现了这些功能，并开始使我们的 API 更接近 NumPy。随着时间的推移，我们期望在适当的地方越来越接近 NumPy 的 API。

稀疏张量

三月份，我们发布了一个支持稀疏张量的小型包，五月份我们发布了稀疏包的 CUDA 支持。这个包体积小，功能有限，用于实现稀疏嵌入和深度学习中常用的稀疏范式。这个包的范畴仍然很小，有扩展它的需求——如果您有兴趣参与扩展稀疏包的工作，请通过我们的讨论区联系我们。

性能

性能始终是一场持续的战斗，尤其是对于 PyTorch 这样的动态框架，它希望最大化灵活性。在过去的一年里，我们在各个方面都提高了性能，从我们的核心 Tensor 库到神经网络算子，全面实现了更快的微优化。

  • 为 Tensor 操作添加了专门的 AVX 和 AVX2 内嵌函数。
  • 为频繁的工作负载（如连接和 Softmax 等许多其他操作）编写了更快的 GPU 内核。
  • 重写了多个神经网络算子的代码（太多无法一一列举），但特别值得注意的是 nn.Embedding 和分组卷积。

全方位降低框架开销10倍

由于 PyTorch 是一个动态图框架，我们在训练循环的每次迭代中都会动态创建一个新的图。因此，框架开销必须很低，或者工作负载必须足够大，以至于框架开销被隐藏。在 8 月份，DyNet 的作者（Graham Neubig 及其团队）展示了它在小型 NLP 模型上比 PyTorch 快得多。这是一个有趣的挑战，我们没有意识到那些大小的模型正在被训练。在持续数月（并仍在进行中）的努力中，我们着手对 PyTorch 内部进行了重大重写，将框架开销从每个操作执行超过 10 微秒降低到仅 1 微秒。

ATen

在我们着手重新设计 PyTorch 内部结构的过程中，我们构建了 ATen C++11 库，该库现在为 PyTorch 后端提供动力。ATen 的 API 与 PyTorch 的 Python API 相似，使其成为 Tensor 计算的便捷 C++ 库。ATen 可以独立于 PyTorch 进行构建和使用。

将模型导出到生产环境 — ONNX 支持和 JIT 编译器

我们收到的常见请求之一是将 PyTorch 模型导出到其他框架。用户在 PyTorch 中进行快速研究周期，完成后，他们希望将其部署到只有 C++ 要求的大型项目中。

考虑到这一点，我们为 PyTorch 构建了一个追踪器，该追踪器可以将 PyTorch 模型导出为中间表示。后续的追踪可以用于更高效地运行当前的 PyTorch 模型（通过对其运行优化过程），或者将其转换为 ONNX 格式，以便将其发送到其他框架，如 Caffe2、MXNet、TensorFlow 等，或者直接发送到硬件加速库，如 CoreML 或 TensorRT。在未来一年内，您将听到更多关于 JIT 编译器性能改进的消息。
