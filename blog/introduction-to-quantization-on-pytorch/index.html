2020年3月26日

PyTorch 量化入门

由 Raghuraman Krishnamoorthi、James Reed、Min Ni、Chris Gottbrath 和 Seth Weidman 编写

在开发机器学习应用时，高效利用服务器端和设备端计算资源非常重要。为了支持在服务器和边缘设备上更高效的部署，PyTorch 添加了对使用熟悉的即时模式 Python API 进行模型量化的支持。

量化利用 8 位整数（int8）指令来减小模型大小并加快推理速度（降低延迟），这可能是模型实现服务质量目标或甚至适应移动设备上可用资源的区别。即使资源并不那么受限，它也可能使您能够部署更大、更精确的模型。量化从 PyTorch 1.3 版本开始提供，并在 PyTorch 1.4 版本发布时，我们在 PyTorch torchvision 0.5 库中发布了 ResNet、ResNext、MobileNetV2、GoogleNet、InceptionV3 和 ShuffleNetV2 的量化模型。

本文概述了 PyTorch 的量化支持及其与 TorchVision 领域库的集成。

什么是量化？

量化指的是使用低精度数据进行计算和内存访问的技术，通常与浮点实现相比使用 int8，这能在多个重要领域实现性能提升：

  • 模型大小减少4倍；
  • 内存带宽减少2-4倍；
  • 由于内存带宽节省和 int8 算术运算的加速，推理速度提高 2-4 倍（具体的加速效果取决于硬件、运行时和模型）。

量化虽然不无额外成本。从根本上讲，量化意味着引入近似，因此这些网络在精度上略低于全浮点精度。这些技术试图最小化全浮点精度和量化精度之间的差距。

我们设计了量化以适应 PyTorch 框架。这意味着：

  1. PyTorch 有对应于量化张量的数据类型，这些数据类型与张量共享许多特性。
  2. 可以使用量化张量编写内核，就像为浮点张量编写的内核一样，以自定义其实现。PyTorch 支持量化模块，用于常见操作，作为 torch.nn.quantized 和 torch.nn.quantized.dynamic 命名空间的一部分。
  3. 量化与 PyTorch 的其他部分兼容：量化模型可追踪和可脚本化。量化方法对于服务器和移动后端几乎相同。可以在模型中轻松混合量化和浮点运算。
  4. 可以使用用户定义的观察器/模拟量化块自定义将浮点张量映射到量化张量的过程。PyTorch 提供了默认实现，适用于大多数用例。

我们在 PyTorch 的 torch.quantization 命名空间中开发了三种量化神经网络的技术，作为量化工具的一部分。

PyTorch 从 1.3 版本开始支持的量化三种模式

  1. 动态量化

    PyTorch 支持的量化方法中最简单的一种称为 动态量化 。这不仅仅涉及将权重转换为 int8 - 如所有量化变体中发生的那样 - 而且还在计算之前实时将激活转换为 int8（因此称为“动态”）。因此，计算将使用高效的 int8 矩阵乘法和卷积实现进行，从而实现更快的计算。然而，激活是以浮点格式读取和写入内存的。

    • PyTorch API：我们在 PyTorch 中提供了一个简单的动态量化 API。 torch.quantization.quantize_dynamic 接收一个模型以及一些其他参数，并生成一个量化模型！我们的 端到端教程 以 BERT 模型为例说明了这一点；虽然教程很长，包含加载预训练模型和其他与量化无关的概念，但量化 BERT 模型的部分非常简单：
    import torch.quantization
quantized_model = torch.quantization.quantize_dynamic(model, {torch.nn.Linear}, dtype=torch.qint8)
    • 请参阅函数 此处 的文档、我们的教程中的端到端示例 此处 和 此处 。

  2. 静态量化

    可以进一步通过将网络转换为同时使用整数算术和 int8 内存访问来提高性能（延迟）。静态量化执行了额外的步骤，即首先将数据批次通过网络，并计算不同激活的结果分布（具体来说，这是通过在不同位置插入“观察器”模块来记录这些分布来完成的）。这些信息用于确定在推理时不同激活应该如何量化（一种简单的技术是将激活范围整个划分为 256 个级别，但我们也支持更复杂的方法）。重要的是，这个额外步骤允许我们在操作之间传递量化值，而不是在每个操作之间将这些值转换为浮点数 - 然后再转换回整数 - 从而实现显著的加速。

    在这次发布中，我们支持了几个功能，使用户能够优化他们的静态量化：

    1. 观察者：您可以自定义观察者模块，这些模块指定了在量化之前如何收集统计数据，以便尝试更先进的量化数据方法。
    2. 运算符融合：您可以将多个运算符融合成一个运算符，这样可以节省内存访问，同时提高运算的数值精度。
    3. 每通道量化：我们可以独立地对卷积/线性层中的每个输出通道的权重进行量化，这可以在几乎相同的速度下实现更高的精度。

    • PyTorch API：

      • 将模块融合，我们使用 torch.quantization.fuse_modules
      • 使用 torch.quantization.prepare 插入观察者
      • 最后，使用 torch.quantization.convert 进行量化

    我们有一个包含量化端到端示例的教程（这个教程还涵盖了我们的第三种量化方法，量化感知训练），但由于我们的简单 API，对预训练模型 myModel 执行后训练静态量化的三条代码行是：

    # set quantization config for server (x86)
deploymentmyModel.qconfig = torch.quantization.get_default_config('fbgemm')

# insert observers
torch.quantization.prepare(myModel, inplace=True)
# Calibrate the model and collect statistics

# convert to quantized version
torch.quantization.convert(myModel, inplace=True)

  3. 量化感知训练

    量化感知训练(QAT) 是第三种方法，通常在这三种方法中精度最高。在 QAT 中，所有权重和激活在训练的前向和反向传播过程中都被“模拟量化”：也就是说，浮点值被四舍五入以模拟 int8 值，但所有计算仍然使用浮点数进行。因此，在训练过程中，所有权重调整都是在“意识到”模型最终将被量化的情况下进行的；因此，这种方法通常比其他两种方法具有更高的精度。

    • PyTorch API：

      • torch.quantization.prepare_qat 向模型量化中插入模拟量化模块。
      • 模拟静态量化 API，torch.quantization.convert 实际上在训练完成后对模型进行一次量化。

    例如，在端到端示例中，我们加载预训练模型 qat_model，然后简单地使用以下方法进行量化感知训练：

    # specify quantization config for QAT
qat_model.qconfig=torch.quantization.get_default_qat_qconfig('fbgemm')

# prepare QAT
torch.quantization.prepare_qat(qat_model, inplace=True)

# convert to quantized version, removing dropout, to check for accuracy on each
epochquantized_model=torch.quantization.convert(qat_model.eval(), inplace=False)

设备和算子支持

量化支持限制为可用算子子集，具体取决于使用的方法，有关支持算子的列表，请参阅 https://pytorch.org/docs/stable/quantization.html 文档。

可用的算子和量化数值也取决于运行量化模型的后端。目前，以下后端仅支持 CPU 推理的量化算子：x86 和 ARM。量化配置（如何量化张量以及量化内核（量化张量的算术运算））取决于后端。可以通过以下方式指定后端：

import torchbackend='fbgemm'
# 'fbgemm' for server, 'qnnpack' for mobile
my_model.qconfig = torch.quantization.get_default_qconfig(backend)
# prepare and convert model
# Set the backend on which the quantized kernels need to be run
torch.backends.quantized.engine=backend

然而，量化感知训练是在全浮点数下进行的，并且可以在 GPU 或 CPU 上运行。量化感知训练通常仅在 CNN 模型中，当训练后静态或动态量化无法达到足够的精度时使用。这可能会发生在高度优化以实现小型化（如 Mobilenet）的模型中。

在 torchvision 中的集成

我们还启用了 torchvision 中最受欢迎的一些模型的支持量化：Googlenet、Inception、Resnet、ResNeXt、Mobilenet 和 Shufflenet。我们将这些更改以三种形式上推到 torchvision 中：

  1. 预训练的量化权重，让您可以直接使用。
  2. 量化准备好的模型定义，以便您可以进行训练后量化或量化感知训练。
  3. 一个用于进行量化感知训练的脚本——虽然，如您下面将学到的，我们发现它对于在 Mobilenet 上实现精度是必要的。
  4. 我们还提供了一个教程 ，展示了您如何使用 torchvision 模型之一进行量化迁移学习。

选择方法

选择使用哪种方案取决于多个因素：

  1. 模型/目标需求：某些模型可能对量化敏感，需要量化感知训练。
  2. 操作符/后端支持：某些后端需要完全量化的操作符。

目前，操作员覆盖范围有限，可能会限制下表中列出的选择：下表提供指导。

模型类型 优选方案 为什么
LSTM/RNN 动态量化 权重的吞吐量受计算/内存带宽主导
BERT/Transformer 动态量化 权重的吞吐量受计算/内存带宽主导
CNN 静态量化 激活值的吞吐量受内存带宽限制
CNN 量化感知训练 在静态量化无法达到精度的情况下

性能结果

量化可以将模型大小减少4倍，并且与浮点实现相比，根据硬件平台和基准测试的模型，速度提高2倍到3倍。以下是一些示例结果：

Model 浮点延迟（毫秒） 量化延迟（毫秒） 推理性能提升 设备 备注
BERT 581 313 1.8倍 Xeon-D2191（1.6GHz） 批大小 = 1，最大序列长度 = 128，单线程，x86-64，动态量化
Resnet-50 214 103 2倍 Xeon-D2191（1.6GHz） 单线程，x86-64，静态量化
Mobilenet-v2 97 17 5.7倍 三星 S9 静态量化，浮点数基于 Caffe2 运行时，未经优化

我们还比较了静态量化模型与浮点模型在 ImageNet 上的准确度。对于动态量化，我们在 GLUE 基准测试的 MRPC 上比较了 BERT 的 F1 分数。

结论

要开始在 PyTorch 中量化您的模型，请从 PyTorch 网站的教程 开始。如果您正在处理序列数据，请从 LSTM 的动态量化 或 BERT 开始。如果您正在处理图像数据，我们建议从 量化迁移学习 教程开始。然后您可以探索 静态后训练量化 。如果您发现后训练量化导致精度下降过高，那么请尝试 量化感知训练 。

如果遇到问题，您可以通过在 discuss.pytorch.org 上发帖来获得社区帮助，使用量化类别来报告与量化相关的问题。
