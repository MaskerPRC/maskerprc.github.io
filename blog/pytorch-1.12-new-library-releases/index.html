2022年6月28日

PyTorch 1.12 版本中的新图书馆更新

由 PyTorch 团队

我们正在对当前的 PyTorch 库进行多项改进，同时发布了 PyTorch 1.12 版本 。这些更新展示了我们致力于开发跨所有领域的通用和可扩展的 API，以使我们的社区更容易在 PyTorch 上构建生态系统项目。

摘要：

  • TorchVision - 添加了多权重支持 API、新的架构、模型变体和预训练权重。请参阅此处的发布说明。
  • TorchAudio - 引入了包括流式 API、CTC 波束搜索解码器和新的波束成形模块和方法在内的 beta 功能。请参阅此处的发布说明。
  • torchtext - 扩展了对可脚本化 BERT 分词器的支持，并添加了 GLUE 基准测试数据集。请参阅发布说明此处 。
  • torchrec - 添加了 EmbeddingModule 基准测试，TwoTower 检索、推理和顺序嵌入的示例，指标，改进的规划器，并展示了与生产组件的集成。请参阅发布说明此处 。
  • torchx - 将在本地工作区开发的 PyTorch 训练器部署到五种不同的调度器上。请参阅发布说明此处 。
  • fbgemm - 为推荐系统推理工作负载添加和改进了内核，包括表批处理嵌入包、锯齿形张量操作和其他特殊情况优化。

TorchVision v0.13

多权重支持 API

TorchVision v0.13 提供了一种新的多权重支持 API，用于将不同权重加载到现有的模型构建方法中：

from torchvision.models import *

# Old weights with accuracy 76.130%
resnet50(weights=ResNet50_Weights.IMAGENET1K_V1)

# New weights with accuracy 80.858%
resnet50(weights=ResNet50_Weights.IMAGENET1K_V2)

# Best available weights (currently alias for IMAGENET1K_V2)
# Note that these weights may change across versions
resnet50(weights=ResNet50_Weights.DEFAULT)

# Strings are also supported
resnet50(weights="IMAGENET1K_V2")

# No weights - random initialization
resnet50(weights=None)

新 API 将权重、预处理转换以及元数据（如标签）等重要细节打包在一起。以下是充分利用它的方法：

from torchvision.io import read_image
from torchvision.models import resnet50, ResNet50_Weights

img = read_image("test/assets/encode_jpeg/grace_hopper_517x606.jpg")

# Step 1: Initialize model with the best available weights
weights = ResNet50_Weights.DEFAULT
model = resnet50(weights=weights)
model.eval()

# Step 2: Initialize the inference transforms
preprocess = weights.transforms()

# Step 3: Apply inference preprocessing transforms
batch = preprocess(img).unsqueeze(0)

# Step 4: Use the model and print the predicted category
prediction = model(batch).squeeze(0).softmax(0)
class_id = prediction.argmax().item()
score = prediction[class_id].item()
category_name = weights.meta["categories"][class_id]
print(f"{category_name}: {100 * score:.1f}%")

您可以在文档中了解更多关于新 API 的信息。为了提供您的反馈，请使用这个专门的 GitHub 问题 。

TorchAudio v0.12

(BETA) 流式 API

StreamReader 是 TorchAudio 的新 I/O API。它由 FFmpeg†支持，并允许用户：

  • 解码音频和视频格式，包括 MP4 和 AAC
  • 处理输入形式，例如本地文件、网络协议、麦克风、摄像头、屏幕捕获和类似文件的对象
  • 逐块迭代并解码，同时更改采样率或帧率
  • 应用音频和视频过滤器，例如低通滤波器和图像缩放
  • 使用 Nvidia 的基于硬件的解码器（NVDEC）解码视频

使用详情，请查阅文档和教程：

  • 媒体流 API - 第 1 部分
  • 媒体流 API - 第 2 部分
  • 基于 Emformer RNN-T 的在线语音识别
  • 基于 Emformer RNN-T 的设备端语音识别
  • 使用 NVDEC 加速视频解码

使用 StreamReader 需要 FFmpeg 库。请安装 FFmpeg。编解码器的支持范围取决于这些库的配置。TorchAudio 官方二进制文件是为与 FFmpeg 4 库兼容而编译的；如果从源代码构建 TorchAudio，则可以使用 FFmpeg 5。

(BETA) CTC 束搜索解码器

TorchAudio 集成了来自 Flashlight (GitHub)的 wav2letter CTC 束搜索解码器。添加此推理时间解码器后，可以使用 TorchAudio 工具运行端到端 CTC 语音识别评估。

支持自定义词典和无词典解码器，两者均兼容 KenLM n-gram 语言模型或无需使用语言模型。TorchAudio 还支持下载 LibriSpeech 数据集的标记、词典和预训练的 KenLM 文件。

关于使用详情，请查阅文档和 ASR 推理教程 。

（BETA）新的波束成形模块和方法

为提高使用灵活性，本版本在 torchaudio.transforms 下增加了两个新的波束成形模块：SoudenMVDR 和 RTFMVDR。与 MVDR 相比的主要区别是：

  • 使用功率谱密度（PSD）和相对传递函数（RTF）矩阵作为输入，而不是时频掩码。该模块可以与直接预测语音和噪声复值短时傅里叶变换（STFT）系数的神经网络集成
  • 在前向方法中添加 'reference_channel' 作为输入参数，以允许用户在模型训练中选择参考通道或在推理过程中动态更改参考通道

除了这两个模块之外，torchaudio.functional 下还添加了新的功能级波束成形方法。这些包括：

  • psd
  • mvdr_weights_souden
  • mvdr_weights_rtf
  • rtf_evd
  • rtf_power
  • 应用波束成形

使用详情请查看 torchaudio.transforms 和 torchaudio.functional 文档，以及基于 MVDR 波束成形的声音增强教程 。

TorchText v0.13

Glue 数据集

我们将 TorchText 中的数据集数量从 22 个增加到 30 个，通过添加 GLUE 基准测试中剩余的 8 个数据集（SST-2 已经支持）。GLUE 数据集的完整列表如下：

  • CoLA ( 论文 )：单句二分类可接受性任务
  • SST-2 ( 论文 )：单句二分类情感任务
  • MRPC ( 论文 )：双句二分类同义任务
  • QQP：双句二元分类释义任务
  • STS-B ( 论文 )：单句到浮点回归句子相似度任务
  • MNLI ( 论文 )：句子三元分类 NLI 任务
  • QNLI ( 论文 )：句子二元分类 QA 和 NLI 任务
  • RTE ( 论文 )：双句二元分类 NLI 任务
  • WNLI ( 论文 )：双句二元分类指代消解和 NLI 任务

可脚本化的 BERT 分词器

TorchText 通过添加 BERT 中使用的 WordPiece 分词器扩展了对可脚本化分词器的支持。这是将输入文本分割成子词单元的常用算法之一，它首次在 《日语和韩语音频搜索》（Schuster et al., 2012） 中提出。

支持 TorchScript 将 BERT 文本预处理功能原生嵌入 C++中，无需依赖 Python 运行时。由于 TorchText 现在支持 CMAKE 构建系统，可以原生地将 torchtext 二进制文件与应用程序代码链接，用户可以轻松集成 BERT 分词器以满足部署需求。

请参阅相应的文档以获取使用详情。

TorchRec v0.2.0

EmbeddingModule + DLRM 基准测试

一组基准测试 ，展示了 TorchRec 基础模块和研究模型的性能特征。

基于 FAISS 的 TwoTower 检索示例

我们提供了一个示例 ，演示了使用 TorchRec 训练一个分布式 TwoTower（即用户-物品）检索模型，该模型使用分片技术。预测的物品嵌入被添加到 IVFPQ FAISS 索引中用于候选生成。检索模型和 KNN 查找被封装在一个 Pytorch 模型中，以实现高效的端到端检索。

集成

我们演示了 TorchRec 与许多在生产环境中与 PyTorch 模型一起使用的常用组件无缝配合，例如系统等

  • 使用 Torchx Ray 调度器在 Ray 集群上训练 TorchRec 模型
  • 使用 NVTabular 在 DLRM 上进行预处理和 DataLoading
  • 使用 TorchArrow 进行即时预处理训练 TorchRec 模型，展示 RecSys 领域的 UDFs

顺序嵌入示例：Bert4Rec

我们提供了一个示例 ，使用 TorchRec 重新实现了 BERT4REC 论文，展示了用于非池化嵌入的 EmbeddingCollection。使用 DistributedModelParallel，我们看到了相对于传统数据并行主义的 35% QPS 提升。

（Beta）规划器

TorchRec 库包含一个内置的规划器 ，该规划器为给定模型选择近最优的划分计划。规划器通过评估一系列提案来尝试识别最佳划分计划，这些提案被静态分析并输入到整数划分器中。规划器能够自动调整适用于广泛硬件设置的计划，使用户能够无缝地从本地开发环境扩展到大规模生产硬件。请参阅此笔记本以获取更详细的教程。

(Beta) 推理

torchrec 推理 是一个支持多 GPU 推理的 C++ 库。torchrec 库用于将使用 torch.package（TorchScript 的替代方案）编写的 Python 模型进行分片。torch.deploy 库用于通过启动携带打包模型的多个 Python 解释器来从 C++ 中提供推理服务，从而绕过全局解释器锁（GIL）。提供了两个示例模型：DLRM 多 GPU（通过 torchrec 分片）和 DLRM 单 GPU。

(Beta) RecMetrics

RecMetrics 是一个 指标 库，用于收集推荐模型的常用工具和优化。它扩展了 torchmetrics。

  • 一个允许用户添加新指标的集中式指标模块
  • 常用指标，包括 AUC、校准、CTR、MSE/RMSE、NE 和吞吐量
  • 优化与指标相关操作，以减少指标计算的开销
  • 检查点

(原型) 单进程批量+融合嵌入

之前 TorchRec 的抽象（EmbeddingBagCollection/EmbeddingCollection）在 FBGEMM 内核上，提供了诸如表批量、优化器融合和 UVM 放置等好处，但只能与 DistributedModelParallel 一起使用。我们已经将这些概念与分片解耦，并引入了融合嵌入袋集合（FusedEmbeddingBagCollection），它可以作为一个独立的模块使用，具有所有上述功能，也可以进行分片。

TorchX v0.2.0

TorchX 是一个作业启动器，它使得在具有许多调度器集成（包括 Kubernetes 和 Slurm）的分布式训练集群中运行 PyTorch 变得更加容易。我们很高兴发布 TorchX 0.2.0 版本，其中包含了许多改进。TorchX 目前正在本地和云环境中投入生产使用。

查看快速入门指南以开始启动本地和远程作业。

工作空间

TorchX 现在支持工作空间，允许用户轻松使用本地工作空间启动训练作业。TorchX 可以自动在基础镜像上构建包含您本地训练代码的补丁，以最小化迭代时间和训练时间。

.torchxconfig

在 .torchxconfig 中指定选项可以让你在每次启动作业时无需输入冗长的 CLI 命令。你还可以定义项目级别的通用配置，并在用户目录中放置配置文件以进行用户级覆盖。

扩展的调度器支持

除了现有的集成之外，TorchX 现在还支持 AWS Batch 和 Ray（实验性） 调度器。

在所有调度器上实现分布式训练

火炬 X 的 dist.ddp 组件现在可以在所有调度器上工作，无需任何配置。使用 torchelastic 并通过内置的 dist.ddp 组件 ，分布式训练工作进程将自动发现彼此。

超参数优化

TorchX 与 Ax 集成，让您可以通过在远程集群上启动搜索试验来扩展超参数优化（HPO）。

文件和设备挂载

TorchX 现已支持 远程文件系统挂载和自定义设备 。这使得您的 PyTorch 作业能够高效访问云存储，如 NFS 或 Lustre。设备挂载功能使得可以使用网络加速器，如 Infiniband 和自定义推理/训练加速器。

FBGemm v0.2.0

FBGEMM 库包含旨在提高 PyTorch 工作负载性能的优化内核。在过去几个月中，我们添加了许多新功能和优化，我们非常高兴向大家报告。

推理表批量嵌入（TBE）

《表批处理嵌入袋》（TBE）算子是推荐系统在 GPU 上进行嵌入查找的基础操作，我们对其进行了以下性能和灵活性方面的增强：

移除了对齐限制

  • 嵌入维度 * 数据类型大小之前必须是 4B 的倍数，现在则是 1B。

统一虚拟内存（UVM）缓存内核优化

  • UVM 缓存内核现在与使用 UVM 缓存的表数量成线性扩展。之前，它具有与所有使用 UVM 缓存的表相似的开销
  • UVM 缓存内核的开销比之前小得多

推理 FP8 表批处理嵌入（TBE）

表批处理嵌入包 （TBE）之前支持 FP32、FP16、INT8、INT4 和 INT2 嵌入权重类型。虽然这些权重类型在许多模型中表现良好，但我们集成了 FP8 权重类型（在 GPU 和 CPU 操作中），以便对我们的模型中的 FP8 进行数值和性能评估。与 INT8 相比，FP8 不需要额外的偏差和缩放存储和计算。此外，下一代 H100 GPU 在 Tensor Core（主要是矩阵乘法操作）上支持 FP8。

锯齿形张量核

我们添加了优化的内核以加速 TorchRec JaggedTensor。JaggedTensor 的目的是处理输入数据的一个维度是“锯齿形”的情况，这意味着给定维度中连续的行在长度上可能不同，这在推荐系统中的稀疏特征输入中很常见。内部表示如下：

优化了 permute102-baddbmm-permute102

在批大小不是模型批大小的情况下，融合各种矩阵乘法是困难的，切换批维度是一个快速解决方案。我们创建了 permute102_baddbmm_permute102 操作，该操作切换第一和第二维度，执行批矩阵乘法，然后切换回来。目前我们只支持 FP16 数据类型的正向传播，并将支持 FP32 类型和反向传播。

优化 dim 0 索引选择的 index_select

index_select 通常用作稀疏操作的一部分。虽然 PyTorch 支持任意维度索引选择的通用 index_select，但其对于 dim 0 索引选择这类特殊情况的性能不佳。因此，我们为 dim 0 实现了一个专门的 index_select。在某些情况下，我们观察到 FBGEMM 的 index_select 比 PyTorch（使用均匀索引分布）的 index_select 性能提升了 1.4 倍。
