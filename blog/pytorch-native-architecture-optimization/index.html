2024 年 9 月 26 日

PyTorch 原生架构优化：torchao

由 PyTorch 团队

我们很高兴正式推出 torchao，这是一个 PyTorch 原生库，通过利用低比特数据类型、量化和稀疏性，使模型更快、更小。torchao 是一个易于使用的工具包，其中的技术（大部分）是用易于阅读的 PyTorch 代码编写的，涵盖了推理和训练。这篇博客将帮助您选择对您的工作负载重要的技术。

我们在 LLama 3 和扩散模型等流行的 GenAI 模型上进行了技术基准测试，并观察到准确度下降很小。除非另有说明，基准测试都是 bf16 在 A100 80GB GPU 上运行的。

我们对 Llama 3 的顶级指标是

  • 使用 autoquant 和仅 int4 权重量化的 hqq，Llama 3 8B 推理速度提高了 97%
  • Llama 3.1 8B 推理在 128K 上下文长度下，峰值 VRAM 降低 73%，使用量化 KV 缓存
  • 使用 H100 上的 float8 训练，Llama 3 70B 预训练速度提升 50%
  • 使用 4 位量化优化器，Llama 3 8B 峰值 VRAM 降低 30%

扩散模型推理的顶级指标

  • 在 flux1.dev 上使用 float8 动态量化推理和 float8 行级缩放，速度提升 53%
  • CogVideoX 模型 VRAM 减少 50%，使用 int8 动态量化

下面我们将介绍 torchao 中的一些技术，您可以将这些技术应用到您的模型中进行推理和训练。

推理

我们推理量化算法适用于包含 nn.Linear 层的任意 PyTorch 模型。可以使用我们的顶级 quantize_ API 选择各种 dtypes 和稀疏布局的权重仅和动态激活量化。

from torchao.quantization import (  
    quantize_,  
    int4_weight_only,  
)  
quantize_(model, int4_weight_only())

有时量化一层可能会因为开销而使模型变慢，所以如果您更希望我们为您选择如何量化模型中的每一层，那么您可以选择运行

model = torchao.autoquant(torch.compile(model, mode='max-autotune'))

API 根据您的模型是计算受限还是内存受限，有几个不同的选项。

from torchao.quantization import (  
    # Memory bound models  
    int4_weight_only,  
    int8_weight_only,

    # Compute bound models  
    int8_dynamic_activation_int8_semi_sparse_weight,  
    int8_dynamic_activation_int8_weight,  
      
    # Device capability 8.9+  
    float8_weight_only,  
    float8_dynamic_activation_float8_weight,  
)

我们与 HuggingFace diffusers 团队在 diffusers-torchao 中进行了广泛的扩散模型基准测试，我们在 Flux.1-Dev 上实现了 53.88%的速度提升，在 CogVideoX-5b 上实现了 27.33%的速度提升。

我们的 API 是可组合的，例如，我们将稀疏性和量化组合起来，为 ViT-H 推理带来了 5%的速度提升。

但也可以进行诸如将权重量化为 int4 以及将 kv 缓存量化为 int8 的操作，以支持在 128K 的完整上下文长度下运行 Llama 3.1 8B，同时占用不到 18.9GB 的 VRAM。

QAT

训练后量化，尤其是在 4 位以下时，可能会遭受严重的精度下降。使用量化感知训练（QAT），我们成功地在 hellaswag 上恢复了高达 96%的精度下降。我们将其集成到 torchtune 的端到端配方中，并附有最小教程。

训练

低精度计算和通信

torchao 提供了易于使用的端到端工作流程，用于降低训练计算和分布式通信的精度，从`torch.nn.Linear`层的 float8 开始。以下是将训练运行的计算 gemms 转换为 float8 的一行代码：

from torchao.float8 import convert_to_float8_training  
convert_to_float8_training(model)

想要了解如何使用 float8 将 LLaMa 3 70B 预训练速度提高 1.5 倍的全端到端示例，请参阅我们的 README 文件、torchtitan 的博客和 float8 食谱。

LLaMa 3 70B 的 float8 预训练性能和精度，与 bfloat16 相比

（来源：https://dev-discuss.pytorch.org/t/enabling-float8-all-gather-in-fsdp2/2359）

我们正在扩展我们的训练工作流程以支持更多数据类型和布局

  1. torchtune 中的 NF4 QLoRA
  2. 原型 int8 训练支持
  3. 加速的 2:4 稀疏训练

低比特优化器

受比特和字节启发，我们还增加了对 8 位和 4 位优化器的原型支持，作为 AdamW 的即插即用替代方案。

from torchao.prototype.low_bit_optim import AdamW8bit, AdamW4bit  
optim = AdamW8bit(model.parameters())

集成

我们一直在积极确保 torchao 在开源中一些最重要的项目中运行良好。

  1. Huggingface transformers 作为推理后端
  2. 在 diffusers-torchao 中作为加速扩散模型的参考实现
  3. 在 HQQ 中实现快速 4 位推理
  4. 在 torchtune 中为 PyTorch 原生 QLoRA 和 QAT 提供配方
  5. 在 torchchat 中实现训练后量化
  6. 在 SGLang 中针对 int4 和 int8 的模型后训练量化

结论

如果您想使您的模型在训练或推理时更快更小，我们希望您会发现 torchao 既有用又易于集成。

pip install torchao

我们对接下来的一些事情感到非常兴奋，从低于 4 位的性能内核，用于高吞吐量推理，扩展到更多层，缩放类型或粒度，MX 硬件支持以及支持更多硬件后端。如果您对上述任何一项感到兴奋，可以关注我们的进展：https://github.com/pytorch/ao

如果您对参与 torchao 项目感兴趣，我们已创建了一份贡献者指南，如果您有任何问题，我们会在 discord.gg/gpumode 的 #torchao 频道上交流。

  3. Mobius Labs 因在量化算法和低比特内核方面的友好交流
  4. HuggingFace transformers 因在战斗测试和集成我们的工作上的帮助
  5. HuggingFace diffusers 因在广泛基准和最佳实践方面的合作
