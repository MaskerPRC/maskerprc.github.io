2023年7月25日

基于 C++的 S3 IO DataPipes 发布

由约翰·何、哈利德·埃尔加莱恩德、罗沙尼·纳格莫特、杨大鸣共同撰写

训练大型深度学习模型需要大量数据集。 亚马逊简单存储服务 （Amazon S3）是一种可扩展的云对象存储服务，用于存储大量训练数据集。机器学习（ML）从业者需要一个高效的数据管道，可以从亚马逊 S3 下载数据，转换数据，并将数据馈送到 GPU 进行高吞吐量、低延迟的训练模型。

在这篇文章中，我们介绍了新的 PyTorch S3 IO DataPipes，包括 S3FileLister 和 S3FileLoader。为了提高内存效率和运行速度，新的 DataPipes 使用 C++扩展来访问 Amazon S3。基准测试显示，S3FileLoader 在从 Amazon S3 下载自然语言处理（NLP）数据集方面比 FSSpecFileOpener 快 59.8%。您可以使用新的 DataPipes 构建 IterDataPipe 训练管道。我们还展示了新的 DataPipe 可以将 Bert 和 ResNet50 的整体训练时间缩短 7%。新的 DataPipes 已集成到开源的 TorchData 0.4.0 和 PyTorch 1.12.0 中。

概述

亚马逊 S3 是一个可扩展的云存储服务，没有数据量限制。从亚马逊 S3 加载数据并馈送到高性能 GPU（如 NVIDIA A100）可能具有挑战性。这需要能够满足 GPU 数据处理速度的高效数据管道。为了帮助解决这个问题，我们发布了一个新的高性能 PyTorch 工具：S3 IO DataPipes。DataPipes 是从 torchdata.datapipes.iter.IterDataPipe 派生的子类，因此它们可以与 IterableDataPipe 接口交互。开发者可以快速构建他们的 DataPipe DAGs，以访问、转换和操作数据，具有洗牌、分片和批量功能。

新的 DataPipes 被设计为对文件格式不可知，亚马逊 S3 数据以二进制大对象（BLOBs）的形式下载。它可以作为一个可组合的构建块，组装一个 DataPipe 图，将表格、NLP 和计算机视觉（CV）数据加载到您的训练管道中。

在内部，新的 S3 IO DataPipes 采用了 C++ S3 处理器和 AWS C++ SDK。一般来说，与 Python 相比，C++实现更节省内存，并且在多线程中有更好的 CPU 核心利用率（没有全局解释器锁）。新的 C++ S3 IO DataPipes 推荐用于在训练大型深度学习模型时进行高吞吐量、低延迟的数据加载。

新的 S3 IO DataPipes 提供了两个一等公民 API：

  • S3FileLister – 列出给定 S3 前缀内的 S3 文件 URL 的可迭代对象。此 API 的功能名称为 list_files_by_s3。
  • S3FileLoader – 从给定 S3 前缀加载 S3 文件的可迭代对象。此 API 的功能名称为 load_files_by_s3。

使用说明

在本节中，我们提供了使用新 S3 IO DataPipes 的说明。我们还提供了一个代码片段：load_files_by_s3()。

从源码构建

新的 S3 IO DataPipes 使用 C++扩展。它默认集成在 torchdata 包中。但是，如果新 DataPipes 在环境中不可用，例如 Windows 上的 Conda，您需要从源码构建。更多信息，请参阅可迭代 Datapipes。

配置

亚马逊 S3 支持全局存储桶。然而，存储桶是在一个区域内创建的。您可以通过使用 __init__() 将区域传递给 DataPipes。或者，您可以将 export AWS_REGION=us-west-2 命令添加到您的 shell 中，或者在代码中使用 os.environ['AWS_REGION'] = 'us-east-1' 设置环境变量。

要读取非公开访问的存储桶中的对象，您必须通过以下方法之一提供 AWS 凭证：

  • 安装和配置 AWS 命令行界面 (AWS CLI)，使用 AWS configure
  • 在本地系统上的 AWS 凭证配置文件中设置凭证，位于 Linux、macOS 或 Unix 的 ~/.aws/credentials
  • 设置 AWS_ACCESS_KEY_ID 和 AWS_SECRET_ACCESS_KEY 环境变量
  • 如果您在 Amazon Elastic Compute Cloud (Amazon EC2) 实例上使用此库，请指定一个 AWS Identity and Access Management (IAM) 角色，然后让 EC2 实例访问该角色

与原始 PyTorch S3 插件进行比较

新的 PyTorch S3 DataPipes 在性能上显著优于原始的 PyTorch S3 插件 。我们已经调整了内部缓冲区大小以优化 S3FileLoader。加载时间以秒为单位进行测量。

在我们的实验中，对于大约 1.5 GiB 的 10 个分片 charades 文件，S3FileLoader 的速度比提高了 3.5 倍。

最佳实践

训练大型深度学习模型可能需要一个拥有数十甚至数百个节点的庞大计算集群。集群中的每个节点可能会生成大量针对特定 S3 分片的数据加载请求。为了避免限制，我们建议将训练数据分片存储在 S3 存储桶和 S3 文件夹中。

为了实现良好的性能，文件大小足够大以并行处理给定文件是有帮助的，但又不至于过大，以免我们触及到在 Amazon S3 上该对象的吞吐量限制，这取决于训练任务。最佳大小可能在 50-200 MB 之间。

结论和下一步

在本文中，我们向您介绍了新的 PyTorch IO DataPipes。新的 DataPipes 使用 aws-sdk-cpp，与基于 Boto3 的数据加载器相比，性能更优。

对于下一步，我们计划通过关注以下功能来提高可用性、性能和功能：

  • S3 授权使用 IAM 角色 – 目前，S3 DataPipes 支持显式访问凭证、实例配置文件和 S3 存储桶策略。然而，在某些情况下，IAM 角色更受欢迎。
  • 双缓冲 – 我们计划提供双缓冲功能以支持多工作线程下载。
  • 本地缓存 – 我们计划使模型训练能够遍历训练数据集进行多次遍历。在第一个 epoch 之后进行本地缓存可以减少从 Amazon S3 的飞行延迟时间，这可以显著加速后续 epochs 的数据检索时间。
  • 可定制配置 – 我们计划公开更多参数，例如内部缓冲区大小、多部分块大小和执行器数量，并允许用户进一步调整数据加载效率。
  • Amazon S3 上传 – 我们计划扩展 S3 DataPipes 以支持检查点上传。
  • 与 fsspec 合并 – fsspec 被用于其他系统，例如 torch.save()。我们可以将新的 S3 DataPipes 与 fsspec 集成，以便它们有更多用例。
