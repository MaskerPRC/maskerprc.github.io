深度学习能耗测量与优化

由崔在元著

本帖由崔在元撰写，他是密歇根大学的博士生，同时也是 ML.ENERGY 创新计划的负责人。

深度学习消耗大量能源。例如，在 AWS p4d 实例上训练单个 200B LLM消耗了大约 11.9 GWh（来源：CIDR 2024 主旨演讲 ），这个数字可以单独为超过一千个平均美国家庭供电一年。

宙斯是一个开源工具箱，用于测量和优化深度学习任务的能源消耗。我们的目标是使基于准确测量的能源优化对各种深度学习任务和配置尽可能容易，通过提供可组合的工具和最小假设来实现。

宙斯主要提供两种工具：

  1. 程序化和命令行 GPU 能耗测量工具
  2. 几款寻找最佳机器学习和/或 GPU 配置的能耗优化工具

宙斯可以造福那些希望的人

  • 测量和优化他们的电费
  • 通过降低功耗来减少 GPU 的散热
  • 报告研发部门的能源消耗
  • 减少电力使用带来的碳足迹

第1部分：测量能量

就像性能优化一样，准确的测量是有效能量优化的基础。像硬件最大功耗这样的流行功耗估计代理有时与实际测量相差甚远。

为了使能量测量尽可能简单和透明，Zeus 核心工具提供的功能是 ZeusMonitor 类。让我们看看实际的代码片段：

from zeus.monitor import ZeusMonitor

# All four GPUs are measured simultaneously.
monitor = ZeusMonitor(gpu_indices=[0,1,2,3])

# Measure total time and energy within the window.
monitor.begin_window("training")
for e in range(100):

    # Measurement windows can arbitrarily be overlapped.
    monitor.begin_window("epoch")
    for x, y in train_dataloader:
        y_hat = model(x)
        loss = criterion(y, y_hat)
        loss.backward()
        optim.step()
    measurement = monitor.end_window("epoch")
    print(f"Epoch {e}: {measurement.time} s, {measurement.total_energy} J")

measurement = monitor.end_window("training")
print(f"Entire training: {measurement.time} s, {measurement.total_energy} J")

上面的代码是一个典型的 PyTorch 训练循环，它使用四个 GPU 进行数据并行训练。在循环内部，我们创建了一个 ZeusMonitor 实例，并传入了一个要监控的 GPU 索引列表。然后，通过使用监控器，我们可以通过调用 begin_window 和 end_window 来测量训练脚本中任意执行窗口的时间和能耗。多个窗口可以以任意方式重叠和嵌套，只要它们的名称不同，就不会影响各自的测量。

ZeusMonitor 添加的额外开销非常小——通常只有个位数毫秒——在窗口周围。这使得 ZeusMonitor 可以在各种应用中使用。例如：

  • ML.ENERGY 领跑榜 ：关于 LLM 文本生成消耗多少能量的第一个开源基准。
  • ML.ENERGY 环球竞技场 ：一个在线服务，允许用户根据响应质量 和 能耗将 LLM 响应并排比较。

查看我们的 博客文章 ，深入了解准确 GPU 能量测量的技术细节。

第2部分：优化能源

让我向您介绍宙斯提供的两个能源优化器。

GlobalPowerLimitOptimizer

GPU 允许用户配置其最大功耗，称为功耗限制 。通常，当您将 GPU 的功耗限制从默认最大值降低时，计算可能会略微变慢，但您将节省不成比例的更多能源。宙斯中的 GlobalPowerLimitOptimizer 会自动在全球范围内为所有 GPU 找到最佳的功耗限制。

from zeus.monitor import ZeusMonitor
from zeus.optimizer.power_limit import GlobalPowerLimitOptimizer

# The optimizer measures time and energy through the ZeusMonitor.
monitor = ZeusMonitor(gpu_indices=[0,1,2,3])
plo = GlobalPowerLimitOptimizer(monitor)

for e in range(100):
    plo.on_epoch_begin()
    for x, y in train_dataloader:
        plo.on_step_begin()

        y_hat = model(x)
        loss = criterion(y, y_hat)
        loss.backward()
        optim.step()

        plo.on_step_end()
    plo.on_epoch_end()

在我们熟悉的 PyTorch 训练循环中，我们已经实例化了 GlobalPowerLimitOptimizer，并通过它传递了一个 ZeusMonitor 的实例，这样优化器就可以看到 GPU 了。然后，我们只需要让优化器知道训练进度（步数和 epoch 边界），优化器就会透明地完成所有必要的性能分析，并收敛到最优的功率限制。

如果你使用的是 HuggingFace 的 Trainer 或 SFTTrainer，集成甚至更简单：

from zeus.monitor import ZeusMonitor
from zeus.optimizer.power_limit import HFGlobalPowerLimitOptimizer

# ZeusMonitor actually auto-detects CUDA_VISIBLE_DEVICES.
monitor = ZeusMonitor()
pl_optimizer = HFGlobalPowerLimitOptimizer(monitor)

# Pass in the optimizer as a Trainer callback. Also works for SFTTrainer.
trainer = Trainer(
    model=model,
    train_dataset=train_dataset,
    ...,
    callbacks=[pl_optimizer],
)

HFGlobalPowerLimitOptimizer 包装了 GlobalPowerLimitOptimizer，以便自动检测步数和 epoch 边界。我们在这里有示例集成示例 ，包括使用 QLoRA 运行 Gemma 7B 监督微调。

现在，我们知道了如何集成优化器，但什么是最优的功率限制？我们知道不同的用户在权衡时间和能源方面可能有不同的偏好，因此我们允许用户指定一个 OptimumSelector（基本上是策略模式 ）来表达他们的需求。

# Built-in strategies for selecting the optimal power limit.
from zeus.optimizer.power_limit import (
    GlobalPowerLimitOptimizer,
    Time,
    Energy,
    MaxSlowdownConstraint,
)

# Minimize energy while tolerating at most 10% slowdown.
plo = GlobalPowerLimitOptimizer(
    monitor,
    MaxSlowdownConstraint(factor=1.1),
)

一些内置策略包括“最小化时间”（ 时间 ，这可能会降低默认的功率限制，因为某些工作负载即使在较低的功率限制下几乎没有任何减速），“最小化能量”（ 能量 ），“介于两者之间”（ZeusCost），以及“在最大减速限制下最小化能量”（MaxSlowdownConstraint）。用户还可以根据需要创建自己的最佳选择器。

管道频率优化器

基于我们的研究论文 Perseus 的管道频率优化器，是我们针对大型模型训练（如 GPT-3）的最新能源优化工作。Perseus 可以在不降低或几乎不降低训练吞吐量的情况下减少大型模型训练的能耗。我们将简要介绍其方法。

上图是使用 1F1B 调度运行四个阶段的管道并行的一次训练迭代的可视化。每个框代表前向或反向计算，并用其功耗着色。

这里的关键观察结果是，当模型被划分为流水线阶段时，很难将它们完美地分割成相等的尺寸。这导致前后箱宽度不一，因此箱之间的计算空闲时间不同。您会注意到，那些较小的箱子可以比较宽的箱子运行得略慢，但整体关键路径（蓝色线）不会发生任何变化。

这正是 Perseus 自动完成的。基于分析，它识别出不在关键路径上的计算箱，并计算出每个箱子的精确减速量，以最小化能耗。当正确执行时，减速的计算将消耗更少的电力和能源，但整个流水线的迭代时间不会改变。

想要开始使用 Perseus，请参阅我们的指南 ！

最后的话

对于那些运行自己的本地计算的用户来说，能源消耗以及随之而来的电费并不是可以轻易忽视的问题。从更大的规模来看，能源消耗不仅仅是电费问题，还包括数据中心电力供应。随着成千上万的 GPU 在集群中运行，寻找稳定、经济、可持续的电力来源来为数据中心供电正变得越来越具有挑战性 。 找到降低能源消耗的方法，其效果超过放缓，可以降低平均功耗，从而有助于解决电力供应问题。

我们希望通过 Zeus 迈出深度学习能源测量和优化的第一步。
