2023年4月14日

使用 PyTorch 2 加速生成式扩散模型

作者：格里戈里·西佐夫、迈克尔·格施温德、哈米德·肖贾纳泽里、德里斯·古索斯、丹尼尔·哈齐扎、克里斯蒂安·普尔施

TL;DR：PyTorch 2.0 夜间版通过使用新的 torch.compile() 编译器和与 PyTorch 2 集成的优化 Multihead Attention 实现了生成扩散模型的即开即用性能提升。

简介

生成式 AI 近期取得的重大进展主要来自去噪扩散模型，这些模型能够根据文本提示生成高质量图像和视频。这一系列模型包括 Imagen、DALLE、Latent Diffusion 等。然而，这一系列模型都存在一个共同的缺点：由于生成图像的过程是通过迭代采样实现的，因此生成速度相对较慢。这使得优化采样循环内部的代码变得尤为重要。

我们以一个流行的开源文本到图像扩散模型的实现为起点，并利用 PyTorch 2 中的两种优化方法加速了其生成过程：编译和快速注意力实现。结合代码中的一些小幅度内存处理改进，这些优化使得相对于原始实现（不使用 xFormers）的推理速度提升了 49%，相对于使用原始代码并使用 xFormers（不包括编译时间）的推理速度提升了 39%，具体取决于 GPU 架构和批量大小。重要的是，这种速度提升无需安装 xFormers 或其他任何额外依赖。

下表显示了在安装了 xFormers 的原始实现和我们的优化版本（集成了 PyTorch 内存高效注意力机制，最初是为 xFormers 库开发和发布的）以及 PyTorch 编译之间的运行时间改进。编译时间不包括在内。

  • 对于像 A100 和 V100 这样的强大 GPU，改进是显著的。对于这些 GPU，改进在批量大小为 1 时最为明显
  • 对于性能较弱的 GPU，我们观察到较小的加速（或在两种情况下略有下降）。这里的批量大小趋势是相反的：对于更大的批量，改进更大

在接下来的章节中，我们描述了应用的优化措施，并提供了详细的基准测试数据，比较了具有各种优化功能开/关的生成时间。

具体来说，我们基准测试了 5 种配置，下面的图表比较了它们在不同 GPU 和批量大小下的绝对性能。有关这些配置的定义，请参阅“基准测试设置和结果”部分。

优化

在这里，我们将更详细地介绍引入到模型代码中的优化。这些优化依赖于最近发布的 PyTorch 2.0 的特性。

优化后的注意力机制

我们优化的代码部分之一是缩放点积注意力。众所周知，注意力是一个计算密集型的操作：原始实现会生成注意力矩阵，导致时间和内存复杂度与序列长度呈二次方关系。扩散模型通常会在 U-Net 的多个部分使用注意力（CrossAttention）作为 Transformer 块的一部分。由于 U-Net 在每个采样步骤都会运行，这成为了一个需要优化的关键点。除了自定义注意力实现，还可以使用 torch.nn.MultiheadAttention，在 PyTorch 2 中，它已经集成了优化的注意力实现。这种优化方案可以简化为以下伪代码：

class CrossAttention(nn.Module):
    def __init__(self, ...):
        # Create matrices: Q, K, V, out_proj
        ...
    def forward(self, x, context=None, mask=None):
       # Compute out = SoftMax(Q*K/sqrt(d))V
       # Return out_proj(out)
       …

被替换为

class CrossAttention(nn.Module):
    def __init__(self, ...):
        self.mha = nn.MultiheadAttention(...)
    def forward(self, x, context):
	return self.mha(x, context, context)

PyTorch 1.13（见此处 ）已经提供了优化的注意力机制的实现，并且被广泛采用（例如，见 HuggingFace transformers 库示例 ）。特别是，它集成了来自 xFormers 库的内存高效注意力机制和来自 https://arxiv.org/abs/2205.14135 的闪速注意力机制。PyTorch 2.0 扩展了这一功能，增加了交叉注意力和自定义内核等额外的注意力函数，以进一步加速，使其适用于扩散模型。

瞬时注意力在具有计算能力 SM 7.5 或 SM 8.x 的 GPU 上可用 - 例如，T4、A10 和 A100，这些都在我们的基准测试中（您可以在此检查每个 NVIDIA GPU 的计算能力 ）。然而，在我们的 A100 测试中，由于注意力头数量少和批量大小小，内存高效注意力在扩散模型特定情况下比瞬时注意力表现更好。PyTorch 理解这一点，在这种情况下，当两者都可用时，它会选择内存高效注意力而不是瞬时注意力（请参阅此处逻辑 ）。为了完全控制注意力后端（内存高效注意力、瞬时注意力、“纯数学”、或任何未来的后端），高级用户可以使用上下文管理器 torch.backends.cuda.sdp_kernel 手动启用和禁用它们。

编译

编译是 PyTorch 2.0 的新功能 ，它通过非常简单的用户体验实现了显著的加速。要调用默认行为，只需将 PyTorch 模块或函数包装在 torch.compile 中：


model = torch.compile(model)

PyTorch 编译器将 Python 代码转换为一系列可高效执行的指令，而不需要 Python 的开销。编译过程在代码首次执行时动态发生。默认情况下，在底层 PyTorch 使用 TorchDynamo 来编译代码，并使用 TorchInductor 来进一步优化它。请参阅 这篇教程 了解更多详情。

虽然上面的单行代码足以进行编译，但某些代码修改可以带来更大的速度提升。特别是，应避免所谓的图断点——PyTorch 无法编译的代码中的位置。与之前的 PyTorch 编译方法（如 TorchScript）不同，PyTorch 2 编译器在这种情况下不会中断。相反，它会回退到 eager 执行——因此代码会运行，但性能会降低。我们对该模型代码进行了一些小的修改，以消除图断点。这包括从编译器不支持库中删除函数，例如 inspect.isfunction 和 einops.rearrange。请参阅这篇 文档 了解有关图断点及其消除方法的更多信息。

理论上，可以在整个扩散采样循环上应用 torch.compile。然而，在实践中，只需要编译 U-Net 就足够了。原因是 torch.compile 还没有循环分析器，它会为采样循环的每次迭代重新编译代码。此外，编译后的采样器代码可能会生成图断裂，因此如果想要从编译版本中获得良好的性能，就需要对其进行调整。

注意，编译 需要 GPU 计算能力 >= SM 7.0 才能在非惰性模式下运行。这涵盖了我们在基准测试中的所有 GPU - T4、V100、A10、A100 - 除了 P100（见完整列表 ）。

其他优化

此外，我们通过消除一些常见陷阱，例如直接在 GPU 上创建张量而不是在 CPU 上创建然后移动到 GPU，提高了 GPU 内存操作的效率。需要此类优化的地方是通过行分析以及查看 CPU/GPU 迹迹和火焰图确定的。

我们有两个版本的代码进行比较： 原始和优化 。在此基础上，还可以开启/关闭几个优化功能（xFormers、PyTorch 内存高效注意力、编译）。总的来说，如引言中所述，我们将对 5 种配置进行基准测试：

  • 没有 xFormers 的原始代码
  • 带有 xFormers 的原始代码
  • 使用纯数学注意力后端且无需编译的优化代码
  • 使用内存高效注意力后端且无需编译的优化代码
  • 使用内存高效注意力后端且需要编译的优化代码

与原始版本相比，我们采用了使用 PyTorch 1.12 和自定义注意力实现的代码版本。而优化版本使用 nn.MultiheadAttention 在 CrossAttention 中，并使用 PyTorch 2.0.0.dev20230111+cu117。它还在 PyTorch 相关代码中进行了几项其他的小优化。

每次运行文本到图像生成脚本会产生几个批次，批次的数量由 CLI 参数 --n_iter 调节。在基准测试中，我们使用了 n_iter = 2，但引入了一个额外的“预热”迭代，这个迭代不会对运行时间产生影响。这对于需要编译的运行是必要的，因为代码第一次运行时会发生编译，因此第一次迭代的运行时间要长于所有后续迭代。为了使比较公平，我们也为所有其他运行引入了这一额外的“预热”迭代。

上表中的数字表示迭代次数 2（加上一个“预热”迭代），提示词为“照片”，种子值为 1，使用 PLMS 采样器，并且启用了自动调整。

基准测试使用了 P100、V100、A100、A10 和 T4 GPU。T4 的基准测试在 Google Colab Pro 上进行。A10 的基准测试在 g5.4xlarge AWS 实例上，每个实例配备 1 个 GPU。

结论与下一步计划

我们已经证明，PyTorch 2 的新特性——编译器和优化的注意力实现——带来了超越或与之前需要安装外部依赖（xFormers）相当的性能提升。PyTorch 通过将其代码库中集成内存高效的注意力机制从 xFormers 中实现这一点。考虑到 xFormers 作为一个最先进的库，在许多情况下需要自定义安装过程和漫长的构建过程，这是一个对用户体验的重大改进。

这项工作可以继续向几个自然方向进行：

  • 我们在这里实现并描述的优化目前仅针对文本到图像推理进行了基准测试。很有趣的是，看看它们如何影响训练性能。PyTorch 编译可以直接应用于训练；启用与 PyTorch 优化注意力训练已在路线图上
  • 我们有意最小化了原始模型代码的更改。进一步的剖析和优化可能带来更多改进
  • 目前编译仅应用于采样器内的 U-Net 模型。由于 U-Net 之外还有很多事情发生（例如，采样循环中的直接操作），编译整个采样器将是有益的。然而，这需要分析编译过程以避免每次采样步骤都需要重新编译
  • 当前代码仅适用于 PLMS 采样器内的编译，但将其扩展到其他采样器应该是微不足道的
  • 除了文本到图像生成之外，扩散模型还被应用于其他任务——图像到图像和修复。测量它们从 PyTorch 2 优化中性能提升将很有趣

尝试使用我们描述的方法提高开源扩散模型的表现，并分享结果！
