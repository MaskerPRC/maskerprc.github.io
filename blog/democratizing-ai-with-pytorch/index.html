2023年2月14日

使用 PyTorch Foundation 和 ROCm™对 PyTorch 的支持民主化 AI

由 AMD 提供

去年，Meta 宣布 PyTorch 加入了 Linux Foundation，作为机器学习项目及社区的中立家园，AMD 作为创始会员和董事会的一部分参与其中，共同推动机器学习项目及社区的发展。

PyTorch 基金会的使命是通过开源原则民主化其软件生态系统，这与 AMD 的核心原则——开放软件生态系统相一致。AMD 致力于通过支持最新一代的硬件、工具、库和其他组件，简化并加速人工智能在广泛的科学发现中的应用，以促进创新。

AMD 与关键 PyTorch 代码库开发者（包括 Meta AI 的员工）共同推出了一系列更新，为 ROCm™ 开源软件生态系统提供了对 AMD Instinct™ 加速器和许多 Radeon™ GPU 的稳定支持。这使得 PyTorch 开发者能够利用 AMD GPU 加速器和 ROCm 构建他们下一个伟大的 AI 解决方案。PyTorch 社区在识别差距、优先处理关键更新、提供性能优化反馈以及支持我们从“Beta”版本过渡到“Stable”版本的过程中提供了巨大帮助，我们对 AMD 和 PyTorch 两个团队之间的紧密合作表示衷心感谢。ROCm 从“Beta”版本升级到“Stable”版本的举措在 PyTorch 1.12 版本（2022 年 6 月）中体现，它为在原生环境中轻松运行 PyTorch 提供了额外支持，无需配置自定义 docker。这是对使用 AMD Instinct 和 ROCm 的 PyTorch 支持质量和性能的信心表现。这些合作努力的成果在以下图 1 中展示的 Microsoft 的 SuperBench 等关键行业基准测试的性能中得到了体现。

“我们非常兴奋地看到 AMD 开发者为 PyTorch 做出贡献并扩展功能，使 AI 模型以更高效、更节能和更可扩展的方式运行。这一点的杰出例子是框架与未来硬件系统之间统一内存方法的领导力，我们期待看到这一功能的进展。”

- Soumith Chintala，PyTorch 首席维护者和 Meta AI 工程总监

AMD CDNA™架构以及 ROCm 和 PyTorch 的渐进式改进，展示了从 AMD Instinct MI100 到最新一代 AMD Instinct MI200 系列 GPU 的单 GPU 模型吞吐量从 ROCm 4.2 到 ROCm 5.3，以及从 PyTorch 1.7 到 PyTorch 1.12 的增长。

图 1：使用 Microsoft Superbench Suite 的 ML 模型性能随代际变化 1, 2, 3

以下是自 PyTorch 1.12 版本发布以来对 ROCm 支持的几个关键更新

PyTorch 上 ROCm 的完整持续集成（CI）

随着 PyTorch 对 ROCm 的支持从“Beta”版升级到“稳定”版，所有函数和特性的提交现在都通过完整的持续集成（CI）流程进行验证。CI 流程有助于确保在预期的 Docker 和 PIP wheel 发布之前，稳定提交的构建和测试过程。

支持 Kineto Profiler

ROCm 现已支持 Kineto 性能分析器，这有助于开发者和用户通过有效的诊断和性能分析工具了解性能瓶颈。该工具还提供改进已知问题和通过 TensorBoard UI 可视化的建议。

添加了关键 PyTorch 库支持

自 ROCm 5.1 和 PyTorch 1.12 开始，PyTorch 生态系统库如 PyTorchText（文本分类）、PyTorchRec（推荐系统库 - RecSys）、PyTorchVision（计算机视觉）、PyTorchAudio（音频和信号处理）得到全面支持。

ROCm 软件堆栈中提供的核心库，包括 MIOpen（卷积模型）、RCCL（ROCm 集体通信）和 rocBLAS（变换器 BLAS），经过进一步优化，以提供新的潜在效率和更高的性能。

MIOpen 在多个方面进行创新，例如通过融合优化内存带宽和 GPU 启动开销，提供自动调优基础设施以克服问题配置的大设计空间，以及实现不同的算法以优化不同滤波器和输入大小的卷积。MIOpen 是第一个公开支持卷积 bfloat16 数据类型的库之一，允许在较低精度下高效训练，同时保持预期的准确性。

RCCL（发音为“Rickle”）是一个独立的库，包含用于 GPU 的标准集体通信例程，实现了全归约、全收集、归约、广播、归约散射、收集、散射和全对全。它支持直接 GPU 到 GPU 的发送和接收操作。RCCL 已针对使用 PCIe®、Infinity Fabric™（GPU 到 GPU）以及使用 InfiniBand Verbs 或 TCP/IP 套接字的网络进行优化，以实现高带宽。RCCL 支持单节点或多节点中安装的任意数量的 GPU，并且可以在单进程或多进程（例如 MPI）应用程序中使用。

除了上述关键亮点外，AMD 和 PyTorch 还共同完成了超过 50 项功能和性能改进，以稳定支持 ROCm。这包括对工具、编译器、运行时、通过 TorchScript 的图优化、INT8 量化路径使用以及 ONNX 运行时集成的改进，其中包括对基于 Navi 21 的 Radeon™ PRO 数据中心显卡的支持，仅举几例。

AITemplate 推理引擎

MetaAI 最近发布了一篇博客，宣布其开源的 AITemplate ( 链接 ) 的发布，该模板支持使用 AMD ROCm 堆栈的 AMD Instinct GPU 加速器进行统一的推理系统。这个基于 Python 的框架可以通过提高 AMD 矩阵核心对 transformer 块的利用率来显著提高性能。这是通过 AMD 可组合内核（CK）库实现的，该库为跨多个架构（包括 GPU 和 CPU）的机器学习 AI 工作负载提供性能关键的内核，通过 HIP 和 C++ 实现。

此外，AITemplate 还提供了对广泛使用的 AI 模型（如 BERT、ResNET、视觉 Transformer、Stable Diffusion 等）的即插即用支持，通过这些预训练模型简化了部署过程。

未来 ROCm 版本将带来什么？

CPU + GPU 统一内存模型

随着系统架构的发展，为了解决大型问题规模和数据集的复杂性，内存管理成为了一个关键的性能瓶颈，需要通过硬件和软件层面的创新来制定一致的策略来解决。AMD 以其有效的数据中心解决方案，将 AMD EPYC™ CPU 内核与其 AMD Instinct GPU 计算单元集成在一起，以真正统一的数据中心 APU（加速处理单元）形式推出，预计将在 2023 年下半年推出。

该软件的工作已经开始与 PyTorch 团队合作，利用统一的 CPU + GPU 内存，以实现快速、低延迟、同步的内存模型，这不仅能够解决 AMD 的问题，还能解决其他 AI 加速器的复杂内存管理问题。我们期待着这一联合努力和即将到来的公告。

致谢

本博客内容重点介绍了 AMD 与包括 Meta 在内的关键 PyTorch 贡献者之间的合作，共同开发许多核心功能，以及微软启用 ONNX Runtime 支持。我们期待与 PyTorch 基金会其他创始成员合作，在下一步和改进中推动 PyTorch 在行业中的民主化和普及。
